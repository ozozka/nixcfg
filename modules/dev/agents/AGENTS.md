# Global Instructions

- Follow the project's documented workflow and conventions; where none are documented, follow
  the conventions visible in its code and history.
- Read the relevant code and documentation before changing them; extend existing owners instead
  of adding parallel implementations.
- Keep changes focused on the request; do not add unrequested features, refactors, or files.
- Ask when a decision belongs to the user instead of guessing.
- Verify before reporting work as done: run the project's checks or the relevant tests, and
  report failed or skipped checks plainly.
- Before writing documentation, find the section that already owns the subject: edit it there,
  link to it elsewhere, and replace outdated text instead of appending. Implementation details
  belong in source comments next to the code.
- Commit only when asked or when the active workflow says so, in focused, atomic commits.
- Never write secrets into files, commits, or logs.
